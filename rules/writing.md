# 문서 작성 규칙 (범용)

> `~/claude-config/CLAUDE.md` 가 import 하는 규칙 파일이다.

---

보고서·매뉴얼·설계서 등 문서를 작성할 때 다음을 지킨다.

- **담백한 보고서체**: "전혀 다릅니다" 같은 구어·과장 표현 대신 "A는 ~하고 B는 ~합니다" 식으로 사실만 담백하게 쓴다.
- **"권장" 표현 지양**: 단정적 권고 대신 "~할 수 있다 / ~하면 개선 가능하다"로 여지를 남긴다. 미구현 항목은 "현재 구현하지 않았으나 ~한 방법으로 가능하다"로 적어 향후 개선 포인트임을 밝힌다.
- **"규정"과 "권장"을 문장에서 구분**한다: 바로 위 항목과 짝이다(그쪽은 *단정을 피하라*, 이쪽은 *필수와 권장을 갈라라*). 반드시 그래야 하는 것은 근거(법령·조문·약정)를 함께 적고, 더 안전할 뿐인 것에는 "권장" "안전하게 하려면" 같은 표지를 붙인다. 표지 없이 섞어 쓰면 상대는 전부 필수로 받아들인다. 2026-08-07 부동산 절차 안내에서 방어적 권고를 법적 요건인 것처럼 쓴 것이 한 세션에 세 번 나왔고(전입 순서·세대 분리·증여 시점), 세 번 다 사용자가 되물어서야 드러났다. **세 건 모두 결론은 안전한 쪽이라 틀렸다는 신호가 나지 않았다** — 안전한 오답이 위험한 오답보다 발견이 늦다.
- **em-dash(—) 미사용**: 쉼표·콜론·괄호로 대체한다.
- **compact 우선**: 장황하게 늘리지 말고 핵심 위주로. 슬라이드/장 수를 늘리기보다 한 면에 밀도 있게 담는다.
- **불확실한 값은 단정하지 않는다**: "대량 유입된다" 대신 "충분한 수량이 확보된다면 ~ 가능하다" 식으로 조건부로 서술한다.
- **예시 데이터는 예시임을 명시**한다(수치·모델을 결론으로 단정하지 않는다).

## 식별 정보 — 라벨과 자기적용 점검

- **머신·환경·프로젝트는 처음부터 중립 라벨로 쓴다.** "나중에 익명화한다"는 성립하지 않는다.
  기록은 지워도 이미 나간 것은 못 지운다. 실측: 소속이 드러나는 머신 라벨로 세션 메모를 적어
  왔고 그 파일이 공개 저장소에 함께 올라가 있었다. 라벨 11회와 내부 경로 구조·프로젝트명이
  노출됐다. 정리하려니 커밋 36개의 히스토리를 다시 써야 했고, **공개돼 있던 기간은 회수할 수
  없었다.**
- **중립 라벨을 정했으면 저장소 전체에 적용한다.** 수집처(인박스·메모)에만 적용하고 산출물을
  그대로 두면 **규칙과 실물이 어긋나고, 규칙만 공개된 채 위반은 남는다.** 위 항목의 짝이며
  같이 확인한다. 실측: 라벨 사고 뒤 중립 체계를 만들었으나 적용된 곳이 로컬 수집 파일 하나뿐이라
  공개 저장소는 옛 호스트명 그대로였고, 같은 기계를 문서마다 다르게 불러 혼선이 실제로 생겼다.
- **산출물이 자기가 서술하는 규칙의 적용 대상인지 마지막에 점검한다.** 해당되면 문서 첫머리에
  취급 주의를 명시한다. 실측: "저장소에서 식별 문자열을 제거하라"는 가이드를 썼는데 그 문서
  자체가 제거 대상 문자열을 명령 예시로 담고 있었다. 저장소에 넣었으면 같은 유출이 반복될 뻔했다.

## 산출물을 어디에 두는가

- **산출물의 정본은 항상 저장소다.** 아티팩트·채팅 출력은 공유용 사본이며 **세션이 끝나면 갱신 경로가 끊긴다.** 시각화·보고서를 요청받아도 **먼저 저장소 안에 정본을 만들고**(도해는 SVG 로 저장해 마크다운에서 상대참조), 아티팩트는 필요할 때 파생물로 낸다. 원격이 없거나 외부 URL 접근이 막힌 환경에서는 아티팩트만 남기면 산출물을 잃는다.
- **"파일로 저장"과 "git 에 기록"을 구분해 말한다.** 두 동작을 "커밋"이라는 한 단어로 뭉뚱그리지 않는다. 목적이 다르다 — 파일을 디스크에 쓰는 것은 **도구가 그 파일을 읽게 하는 것**(마크다운 렌더, 스크립트 실행, 설정 로드)이고, git 에 기록하는 것은 **이력과 공유**를 위한 것이다. 하나만 해도 되는 경우가 많다. 작업 보고 시 **어느 단계까지 했는지 명시**한다.
- **식별 정보를 담은 산출물은 저장소 밖 로컬에 두고 권한을 600 으로 준다.** 어느 저장소에도 커밋하지 않는다는 것을 문서 머리말에 적어 둔다 — 다음 세션이 그 사실을 모른다.

## 인쇄·PDF 로 뽑을 때

- **캔버스를 축소해 배치할 때 `transform: scale()` 을 쓰지 않는다. `zoom` 을 쓴다.** 인쇄 경로는 축소 전 레이아웃 크기로 페이지를 잘라내므로, 화면에서 멀쩡한 것이 PDF 에서 잘린다. 실측: 2026-08-08 청첩장 시안에서 1200×832px 캔버스를 `scale(0.945)` 로 줄여 786px 프레임에 넣었더니 **하단 5.5%(786/832 = 94.5%)가 PDF 에서 사라졌다.** 한 시안은 이름 한 줄이 통째로 없어졌는데 문서를 눈으로 보고도 찾지 못했다. `zoom` 은 레이아웃 자체를 줄이므로 용지와 맞는다.
- **산출물이 이상한데 원인이 안 보이면 눈에 보이는 기준선을 넣고 다시 만든다.** 위 잘림도 캔버스 경계에 진단선을 긋고 다시 뽑아서야 잘리는 위치가 드러났다. 원본과 눈으로 비교하는 것보다 빠르다.

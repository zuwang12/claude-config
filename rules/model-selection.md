# 모델·노력·속도 선택

> `~/claude-config/CLAUDE.md` 가 import 하는 규칙 파일이다. 이 파일에는 모델 ID·가격·
> effort 권장값을 적지 않는다. 그건 낡는다. 최신 값은 항상 `claude-api` 스킬에서 읽는다.

---

## 작업 시작 시 — 모델·노력·속도 추천 (먼저 읽을 것)

사용자는 작업 성격에 맞는 설정을 스스로 예단하기 어렵다고 명시했다.
**추천은 Claude가 하고, 전환은 사용자가 수동으로 한다.**

### 트리거

새 작업을 시작할 때, 또는 진행 중 작업 성격이 바뀔 때(조사 → 판정, 판정 → 구현) 한 번 판단한다.
**사소한 작업에는 하지 않는다** — 단순 질의응답·파일 한 개 수정·명령어 한 줄에는 침묵한다.
같은 세션에서 성격이 안 바뀌었으면 다시 말하지 않는다.

### 절차

1. **값을 기억에서 꺼내지 말 것.** `claude-api` 스킬을 먼저 로드해 현재 모델 카탈로그·가격·
   effort 권장·fast mode 지원 모델을 확인한다. 이 스킬은 Claude Code에 번들되어 앱과 함께
   갱신되므로 항상 그 시점의 최신이다.
2. 작업을 성격으로 분류한다: 도구 fan-out 중심인가 / 단일 장기 추론인가 / 코딩·에이전틱인가 /
   지연이 중요한 대화인가.
3. **세 축을 따로 판단한다.** 모델만이 축이 아니다.
   - **모델** — 기본은 최신 Opus. 그보다 상위 티어는 "가장 어려운 추론"일 때만.
     하위 티어(Sonnet·Haiku)는 메인 루프에 권하지 않는다 — 쓸 자리는 아래
     「하위 티어(Sonnet·Haiku)를 쓸 자리」 참고.
   - **effort** — 실질적인 비용/품질 레버. 최신 Opus는 낮은 effort도 강하므로
     위에서 시작해 아래로 스윕하는 편이 낫다.
   - **fast mode** — 속도 프리미엄. 단가가 상위 티어와 같을 수 있으니 스킬에서 확인할 것.
4. 아래 형식으로 **한 번만** 말하고 계속 진행한다. 사용자 응답을 기다리며 멈추지 않는다
   (3단계 분업의 정지 규칙에 해당하는 경우는 예외 — 그때는 멈춘다).

```
💡 이 작업엔 <모델> / effort <값> / fast <on|off> 를 권합니다.
   이유: <한 줄>
   전환: <해당 표면에서의 방법. 조절 불가한 축이면 "이 환경에선 조절 불가"라고 명시>
   (현재 설정 그대로 진행합니다 — 바꾸시려면 지금 바꾸세요)
```

5. 스킬이 그 환경에 없거나 로드에 실패하면 **추측해서 표를 지어내지 말고**
   "모델 가이드를 확인할 수 없어 추천을 생략합니다"라고 한 줄 남기고 넘어간다.

### 응답 끝 — 사후 기록 (위 사전 추천과 **별개로, 둘 다 한다**)

위 트리거는 **앞으로 할 작업**에 대한 사전 추천이고 작업당 한 번이다. 이것은 **방금 낸
응답**에 대한 사후 평가이고 응답마다다. 대체 관계가 아니다 — 사전은 지금 무엇으로 바꿀지를
정해 주고, 사후는 **그 판단이 맞았는지 재는 계기**가 된다.

`rules/writing.md` 「응답 형식 — 채팅 답변」의 요약 블록 끝에 한 줄 붙인다.
**적용 범위도 그 절과 같다** — 한 줄 답변·되묻기에는 붙이지 않는다.

```
이 응답에 적합했던 설정: <모델> / effort <값> / fast <on|off>
  <한 줄 이유>
```

- **실제로 돈 설정이 아니라 「이 정도면 됐다」를 적는다.** 현재 설정보다 **낮은** 값이
  충분했으면 낮게 적는 것이 이 기록의 값어치다. 매번 현재 설정을 추인하면 계기가 죽는다.
- **값은 세션당 한 번만 확인한다.** 세션에서 처음 이 기록을 쓸 때 `claude-api` 스킬을
  1회 로드하고 그 값을 세션 내내 쓴다(컨텍스트에 남는다). **매 응답마다 다시 읽지 않는다.**
- 스킬을 못 읽은 세션에서는 **모델 ID·effort 값을 기억에서 꺼내지 말고**
  "설정 기록 생략(모델 가이드 미확인)"이라고 적는다. 위 5번과 같은 원칙이다.

## 모델 전환 프로토콜 — 단계별 분업 + 정지 지점

**기본은 Opus.** 단 아래 **3단계 분업**에 해당하는 작업이면, 각 단계 경계에서
**작업을 멈추고 사용자에게 모델 전환을 안내**한다. 나는 모델을 스스로 못 바꾼다.

### 1. 3단계 분업

| 단계 | 성격 | 모델 | 이유 |
|---|---|---|---|
| **1. 조사·수집** | 웹조사 · 데이터 확인 · 코드 탐색 · 파일 위치 파악 | **Opus** | 도구 fan-out·병렬 검색이 병목. 상위 티어를 써도 이득 없이 단가만 오름 |
| **2. 종합·판정** | 대용량 문서를 통째로 읽고 심층 추론·판정 | **Fable** | 긴 호흡 단일 추론이 강점. **컨텍스트 크기는 근거가 아니다** — Opus와 동일하다 |
| **3. 실행·반영** | 코드 작성·수정 · 실행·검증 루프 · 문서 갱신 | **Opus** | 도구 주도 작업. Fable 쓸 이유 없음 |

**판단 기준**: "대용량 기존 문서를 읽고 **방향을 재판정**해야 하는가" — 그렇다면 분업,
아니면 Opus 단독. 단순 코딩·버그 수정·질의응답에 3단계 분업은 오버헤드다.

### 1-b. 하위 티어(Sonnet·Haiku)를 쓸 자리

**메인 루프는 Opus 유지가 기본이다.** Max 구독에서는 달러가 아니라 쿼터가 줄어들 뿐이라,
하위 티어의 이득은 "판단이 거의 필요 없는 작업"에서만 나온다. 아래 두 경우만 고려한다.

| 경우 | 쓸 곳 | 근거 |
|---|---|---|
| **기계적 대량처리** | 서브에이전트 모델 오버라이드 | 파일 일괄 변환·로그 파싱·단순 분류처럼 판단이 없는 fan-out. 메인 루프는 Opus로 두고 서브에이전트만 내린다 (`Agent` 도구의 `model` 파라미터 / `.claude/agents/*.md` frontmatter) |
| **쿼터가 임박** | 메인 루프를 Sonnet으로 | 사용량이 80%에 근접했는데 남은 작업이 코딩·에이전틱이면, 최신 Sonnet은 Opus에 근접한다. Haiku로 내리는 건 이 경우에도 과하다 |

**하지 않을 것**:
- 비용을 이유로 메인 루프를 Haiku로 내리지 않는다. 판단 품질 손실이 재작업으로 돌아온다.
- 하위 티어로 내리기 **전에 effort를 먼저 낮춘다** (아래 「비용 감각」 절). 대개 그쪽이 더 나은 지점이다.
- 3단계 분업의 2단계(종합·판정)에는 하위 티어를 쓰지 않는다. 그 단계는 애초에 상향 전환하는 자리다.

### 2. 정지 규칙

- **1단계가 끝나면 거기서 멈춘다.** 2단계로 그냥 넘어가지 않는다.
- 멈출 때 반드시 이 형식으로 안내한다:

  ```
  🛑 여기서 Claude Fable 5로 전환해 주세요.
     (데스크톱/웹 앱: 모델 선택 메뉴 / 터미널: `/model claude-fable-5`)
  전환 후 "2단계 진행해 줘"라고 하시면 됩니다.

  2단계 입력 파일:
    <경로1>
    <경로2>
  2단계에서 판정할 것:
    1. <질문>
    2. <질문>
  ```

- **2단계가 끝나면 다시 멈추고** Claude Opus 5 복귀를 안내한다
  (데스크톱/웹 앱: 모델 선택 메뉴 / 터미널: `/model claude-opus-5`).
  이때 3단계 실행 목록을 함께 제시한다.
- 사용자가 "그냥 진행해"라고 하면 전환 없이 계속한다. **추천만 하고 판단은 사용자에게.**
- ⚠️ **모델 전환은 같은 세션에서 하지 않는다. 세션을 닫고 새로 연다.**
  프롬프트 캐시는 모델별로 분리돼 있어서, 세션 중간에 모델을 바꾸면 그때까지 쌓인
  대화 이력 전체가 새 모델에서 통째로 재처리된다. 1단계에서 이력이 길어진 상태로
  2단계 모델로 갈아타는 것이 가장 비싼 패턴이다. 아래 「단계별 산출물 규약」의
  "산출물을 파일로 남긴다"가 이걸 막기 위한 것이다 — 파일로 넘기고
  **새 세션**에서 2단계를 시작한다.
  자세한 근거는 `rules/session.md` 의 「세션 수명」 절.

### 3. 단계별 산출물 규약

**1단계** — 2단계는 **다른 모델·다른 컨텍스트**에서 시작하므로 산출물이 자족적이어야 한다:
- 조사 결과를 **파일로 남긴다**(`notes_<날짜>_<주제>.md`). 채팅에만 남기지 않는다.
- 문서 상단에 "이것은 종합 전 raw material"임을 명시하고 **판정·결론을 내리지 않는다**
  (1단계가 미리 결론 내면 2단계가 그걸 추인하는 편향이 생긴다).
- 문서 끝에 **2단계 입력 파일 목록**과 **판정할 질문 목록**을 적는다.

**2단계** — 기존 문서를 **덮어쓰지 말고 증분(v2) 문서로** 낸다:
- 원본 보존 + "서로 다른 판정이 나면 이 문서가 우선한다"를 명시.
- 끝에 **3단계 실행 목록**(코드 / 문서 / **하지 말 것**)을 남긴다.
- **"하지 말 것"이 특히 중요하다** — 기각 판정이 기록되지 않으면 다음 세션이 다시 시도한다.
- 결론이 실험 결과에 의존하면 **분기별 서사를 미리 적어 둔다**("A>B면 …, A≈B면 …").
  나중에 결과만 보고 사후 합리화하는 것을 막는다.

### 4. 비용 감각

- **구체적 단가를 여기에 적지 않는다.** 가격은 바뀐다 — 필요할 때 `claude-api` 스킬에서 읽는다.
- 상위 티어는 Opus보다 비싸다. **Max 구독에서는 달러 청구가 아니라 사용량 쿼터가
  그 배수만큼 빨리 소진된다** — 방향은 같으니 **품질 이득이 그 값을 정당화할 때만** 전환을 권한다.
- 사용자는 Max x20이며 사용량 80% 미만을 원한다.
- **모델을 올리기 전에 effort를 먼저 조절해 볼 것.** 최신 Opus는 낮은 effort에서도 강해서,
  모델 전환보다 effort 조절이 더 나은 비용/품질 지점을 주는 경우가 많다.
- **fast mode는 공짜가 아니다** — 단가가 상위 티어와 같을 수 있다. 스킬에서 확인하고 권할 것.
- **판정 입력이 아직 안 모였으면 전환을 미룬다** — 미완성 데이터로 판정하면
  곧 다시 해야 하고, 비싼 값을 두 번 낸다.
- 애매하면 Opus.

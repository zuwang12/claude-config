# 세션 — 수명 · 시작 · 종료

> `~/claude-config/CLAUDE.md` 가 import 하는 규칙 파일이다.

---

## 세션 수명 — 언제 닫고 새로 여는가

사용자는 세션을 언제 끊어야 하는지 스스로 판단하기 어렵다고 명시했다.
**닫을 때가 됐다고 판단되면 Claude가 먼저 말하고 멈춘다.**

### 1. 왜 중요한가 (비용 구조)

- API는 stateless라 **매 턴마다 대화 전체를 다시 보낸다.** 이력이 길수록 턴당 비용이 커진다.
- 프롬프트 캐시가 반복 구간을 약 0.1배로 깎아 주지만 **TTL이 1시간**이다.
- TTL이 지나면 다음 턴에서 누적 이력 **전체를 캐시에 다시 쓰는 비용(약 1.25배)** 을 한 번에 낸다.

→ **가장 비싼 패턴: 어제 길게 쓴 세션을 오늘 이어서 여는 것.**
이력은 크고 캐시는 식어 있다. "이어서" 한 마디에 누적 이력 전체가 재청구된다.
이력이 20만 토큰이면 그 한 턴에 25만 토큰 상당이 나간다.

→ **반대로, 열려만 있고 입력이 없는 세션은 토큰을 전혀 쓰지 않는다.**
백그라운드 과금이 없다. 세션이 여러 개 떠 있다는 사실 자체는 쿼터와 무관하다
(메모리는 다르다 — 세션당 약 400MB, 아래 「3. 세션 아카이브」).

### 2. 닫아야 하는 상황 — 발견하면 멈추고 컨펌받는다

| 상황 | 이유 |
|---|---|
| **모델을 바꿔야 할 때** | 캐시가 모델별로 분리돼 이력 전체가 재처리된다 (`rules/model-selection.md` 「2. 정지 규칙」의 캐시 경고 참고) |
| **작업 성격이 바뀔 때** (조사 → 판정, 판정 → 구현) | 앞 단계 이력이 뒤 단계에 필요 없는데 매 턴 재전송된다 |
| **하루 이상 끊겼다가 재개할 때** | 캐시가 식어 최악 패턴이 된다. 새 세션 + 문서 인수인계가 싸다 |
| **compaction이 돌기 시작할 때** | 컨텍스트가 찼다는 신호. compaction 자체도 토큰을 쓰고 정확도를 잃는다 |

반대로 **같은 작업을 1시간 안에 계속할 때는 세션을 유지한다.** 캐시 히트라 가장 싸다.
잦은 세션 교체는 컨텍스트 재구축 비용만 늘린다.

**멈출 때 반드시 이 형식으로 안내한다:**

```
🛑 여기서 세션을 닫고 새로 여는 것을 권합니다.
   이유: <위 표의 어느 상황인지 한 줄>
   지금 닫지 않으면: <다음 턴에 어떤 비용/위험이 생기는지 한 줄>

닫기 전 처리할 것:
  - 미커밋: <저장소별 상태, 없으면 "없음">
  - CLAUDE.md/스킬 갱신 후보: <있으면 항목, 없으면 "없음">
  - 실행 중 백그라운드 작업: <있으면 PID, 없으면 "없음">

새 세션 인수인계 파일:
  <경로>
```

**멈춘다는 것은 사용자 응답을 기다린다는 뜻이다.** 안내만 하고 계속 진행하지 않는다.
사용자가 "그냥 진행해"라고 하면 그대로 계속한다. **판단은 사용자에게.**

### 3. 세션 아카이브 (닫기)

앱 왼쪽 목록의 세션 메뉴에서, 또는 사용자가 "오래된 세션 정리해 줘"라고 하면
`archive_session` 도구로 처리한다. 데스크탑 앱 내장 기능이라 별도 설치·인증이 없다.

아카이브는 **프로세스를 정지시키고 worktree를 정리한다.** 목록에서 빠지지만
Archived 목록에서 다시 열 수 있고, 트랜스크립트와 메모리 파일은 남는다.

⚠️ **아카이브 전에 반드시 확인한다:**

1. **worktree 여부** — `get_session`으로 `cwd`와 `originCwd`를 비교한다. 다르거나
   worktree/branch 필드가 있으면 **격리 worktree 세션**이고, 아카이브하면 그 안의
   **미커밋 수정이 사라진다.** 같으면 실제 디렉터리에서 돌던 세션이라 파일은 안전하다.
2. **git 상태** — 해당 `cwd`의 미커밋 수정을 확인해 보고한다.
3. **`isRunning`** — 살아 있으면 진행 중 작업이 죽는다. 시작 시각을 함께 보고한다.

**추측으로 아카이브하지 않는다.** 사용자가 특정 세션을 지목해 동의한 뒤에만 호출한다.

메모리 회수 효과는 세션당 약 400MB + 그 세션이 띄운 MCP 서버 몫이다.
swap 없는 기계에서는 무시할 수준이 아니지만, **쿼터 절약 효과는 없다**(위 「1. 왜 중요한가」).

### 4. 자동 감시 (훅)

위 「2. 닫아야 하는 상황」의 교체 시점을 사람이 매번 눈치채기 어렵다. 훅으로 감시한다.
**훅은 셸에서 돌고 모델을 호출하지 않으므로 토큰 비용이 0이다.**
세션 끝에 "정리해 줘"라고 하는 것이 가장 비싼 순간이므로, 상태를 작업 중에 미리 쌓아 둔다.

| 이벤트 | 스크립트 (`snippets/hooks/`) | 하는 일 |
|---|---|---|
| `Stop` | `session-snapshot.sh` | 매 턴 끝에 branch·미커밋·미push를 파일로 기록 (`async: true`) |
| `PreCompact` | `precompact-warn.sh` | compaction 직전에 "세션 교체 시점" 경고 + 미커밋 개수 |
| `SessionStart` | `session-restore.sh` | 같은 디렉터리의 이전 상태를 컨텍스트로 주입 |

상태 파일은 `~/.claude/session-state/<경로를 -로 치환>.txt`. git 저장소가 아니면 조용히 종료한다.

**새 기계에 설치** — 스크립트는 git으로 내려오지만 **등록은 기계마다 수동**이다.
`~/.claude/`는 로컬이라 공유되지 않는다.

⚠️ **저장소 경로를 직접 가리키지 않는다. `~/.claude/hooks/` 로 복사해서 쓴다.**
심볼릭 링크도 쓰지 않는다. 저장소를 가리키면 `pull` 하는 순간 **검토 없이 실행 코드가 바뀐다.**
복사 방식이면 복사 시점에 검토가 한 번 들어가고, 그 검토가 유일한 방어선이다.

1. 복사부터 한다. **설정을 먼저 바꾸면 그 사이 훅이 조용히 실패한다.**

```bash
mkdir -p ~/.claude/hooks && cp ~/claude-config/snippets/hooks/*.sh ~/.claude/hooks/ && chmod +x ~/.claude/hooks/*.sh
```

2. 복사본이 도는지 파이프로 확인한다(훅은 턴 밖에서 발화해 그 자리 검증이 안 된다).

```bash
for f in ~/.claude/hooks/*.sh; do echo '{}' | "$f" >/dev/null && echo "OK $f" || echo "FAIL $f"; done
```

3. 그 기계의 `~/.claude/settings.json`에 아래를 **병합**한다(기존 키를 지우지 말 것).

```json
"hooks": {
  "Stop":         [{"hooks": [{"type": "command", "command": "$HOME/.claude/hooks/session-snapshot.sh", "timeout": 10, "async": true}]}],
  "PreCompact":   [{"hooks": [{"type": "command", "command": "$HOME/.claude/hooks/precompact-warn.sh",  "timeout": 10}]}],
  "SessionStart": [{"hooks": [{"type": "command", "command": "$HOME/.claude/hooks/session-restore.sh",  "timeout": 10}]}]
}
```

**갱신할 때도 같다.** `pull` 후 `snippets/hooks/` 의 diff 를 먼저 읽고, 납득한 뒤에 다시 복사한다.
복사를 잊으면 옛 버전이 계속 돈다 — 저장소 참조 방식과 반대 방향의 실패다.

**복사 전 검토 시 볼 것** — `session-restore.sh` 는 세션 시작마다 `~/claude-config` 에
**`git fetch` 를 한 번 돈다**(`timeout 5`, 실패 시 조용히 통과). 네트워크를 건드리는 유일한
훅이므로, 그 동작을 원하지 않는 기계에서는 해당 블록을 지우고 복사한다.

⚠️ 주의:
- **`jq`가 없는 기계가 있다.** 훅 예제 대부분이 jq를 쓰므로 `python3`로 대체했다.
  이 기계의 python은 3.8이라 3.8 호환 문법만 쓴다.
- 훅을 추가한 뒤에는 앱에서 **`/hooks` 를 한 번 열거나 세션을 재시작**해야 반영된다.
  설정 감시자는 세션 시작 시점에 설정 파일이 있던 디렉터리만 본다.
- `Stop`·`PreCompact`·`SessionStart`는 턴 밖에서 발생해 **그 자리에서 발화 검증이 불가능하다.**
  파이프 테스트(`echo '{}' | <스크립트>`)로 명령 자체만 검증하고 넘어간다.

## 세션 시작 — 사용자가 "이어서" 라고만 하면

사용자는 세션마다 다른 문장을 외우지 않는다. **"이어서"**(또는 "이어서 진행", "시작", "진행상황") 한 마디면 아래를 **묻지 말고 순서대로 수행**한 뒤 보고한다. 어떤 프로젝트인지는 작업 디렉터리로 판별한다.

1. **실행 중인 백그라운드 작업부터 확인한다.** 장시간 작업은 분리해 돌리므로 앱·PC를 꺼도 계속된다 — **세션이 끊긴 사이 끝나 있는 것이 정상**이다.
   ⚠️ `pkill -f`·`grep -f`는 **자기 명령줄까지 매칭**한다. 자기를 죽이거나 '실행 중'으로 오판하기 쉬우니 **PID로 다룬다.**
   ⚠️ `ps`는 `-p PID`를 `--no-headers`보다 **앞**에 둔다. 순서가 틀리면 전 프로세스를 쏟아낸다.
2. **완료 결과를 회수한다.** 감시 스크립트의 로그·완료 마커가 최신 상태다.
   ⚠️ **stale 마커 주의** — 이전 실행이 남긴 `.done`을 새 실행의 완료로 오인하지 않는다. 시각을 확인하고 새 작업 전에 옛 마커를 치운다.
3. **최신 진행 문서를 읽는다.** 날짜가 가장 최근인 파일. ⚠️ 오래된 요약이 최신 판정과 어긋날 수 있다.
4. **커밋 이력을 본다.** 저장소가 여러 개면 각각. `git log --oneline -8` · `git status --porcelain`
5. **보고하고 멈춘다.** 돌던 작업 결과 · 현재 위치 · **다음 할 일 후보**를 제시하고 지시를 기다린다. 실행은 승인 후 — 특히 과금·장시간 작업.

**병렬 세션 주의**: 다른 창·다른 PC에 세션이 열려 있으면 memory·git·파일이 충돌한다. 1번에서 낯선 프로세스가 보이거나 memory 수정 시각이 방금이면 **먼저 사용자에게 확인**한다.

## 세션 종료 — 사용자가 "세션종료준비" 라고 하면

사용자는 세션을 닫기 전에 남길 것과 위험을 한 번에 점검받고 싶어 한다. **"세션종료준비"**(또는 "세션닫을준비", "종료 준비", "마무리 점검", "닫기 전 점검") 한 마디면 아래를 묻지 말고 순서대로 점검한 뒤 보고한다. **실제 저장·커밋·삭제는 하지 않고, 무엇을 할지 후보만 제시하고 멈춘다.**

이 절은 **사용자가 트리거했을 때**의 점검 절차다. **Claude가 먼저 "닫을 때가 됐다"고 판단하는 기준**은 위 「세션 수명」 절에 있다. 그쪽에서 멈췄다면 이어서 이 절을 수행한다.

1. **실행 중인 백그라운드 작업을 확인한다.** 돌고 있으면 세션을 닫아도 계속되며, 닫힌 사이 끝나는 것이 정상이다. **죽이지 않는다**(사용자가 명시적으로 요청할 때만). PID로 다루고 `pkill -f`·`grep -f`의 자기 매칭에 주의한다.
2. **세션 전용 임시물을 확인한다.** 다만 ⚠️ **회수를 이 시점에 하려 하면 늦다** — 스크래치패드는 세션 종료를 기다려 주지 않는다. 실제로 세션이 살아 있는 동안 먼저 비워져 분석 스크립트를 잃은 적이 있다(2026-07-28, pcb_viz). **한 번 쓰고 버릴 것이 아니면 만드는 순간 영구 경로에 만든다**(`~/Developer/`·프로젝트 폴더). 종료 점검에서는 남은 것이 없는지 확인만 한다.
3. **git 상태를 저장소별로 확인한다.** 미커밋 수정·미push 커밋을 `git status --porcelain`·`git rev-list --left-right --count`로 훑어 보고한다. ⚠️ **커밋·push는 자동으로 하지 않는다**(사용자 승인 후에만). 특히 전역 공유 config는 검토 없이 건드리지 않는다.
4. **CLAUDE.md·스킬 갱신 후보를 가려낸다.** 이번 세션에서 나온 비자명한 사실·오진 교정·재발방지 사항을 **반드시 한 번 훑는다**(없으면 "없음"이라고 명시한다. 조용히 건너뛰지 않는다). 넣을 곳: 프로젝트 한정이면 프로젝트 문서/CLAUDE.md, 범용이면 `~/claude-config/_inbox.md`(확정 규칙이 아니라 **후보**로 append), 특정 도구 사용법이면 해당 스킬, 세션 간 사실이면 메모리. ⚠️ **어디에 넣을지·넣을지 여부는 사용자에게 확인**한다. 전역 공유 config는 4대에 전파되므로 특히 그렇다.
   - 범용 규칙을 `rules/` 아래 파일에 **직접 쓰지 않는다.** `_inbox.md`에 후보로 append하고, 승격은 별도로 한 세션이 몰아서 한다(루트 `CLAUDE.md`의 「규칙 후보 수집함」 절).
5. **자격증명 노출을 점검한다.** 세션 중 토큰·비밀키가 대화창에 평문으로 노출됐으면 재발급을 안내한다.
6. **아카이브 대상을 점검한다.** 이 세션과 다른 오래된 세션 중 정리 후보가 있으면 제시한다. ⚠️ 아카이브는 **프로세스를 죽이고 worktree를 정리**하므로, 위 「세션 수명」의 「3. 세션 아카이브」에 있는 확인 3가지(worktree 여부·git 상태·`isRunning`)를 먼저 수행한다. **승인 없이 호출하지 않는다.**
7. **보고하고 멈춘다.** 이미 안전한 것 / 아직 결정이 필요한 것(커밋? CLAUDE.md 갱신? 메모리? 파일 복사? 토큰 재발급? 아카이브?) / 여전히 실행 중인 것으로 나눠 정리하고 지시를 기다린다.

**병렬 세션 주의**: 다른 창·다른 PC에 세션이 열려 있으면 이쪽에서 커밋·정리하는 사이 충돌할 수 있다. 낯선 미커밋 수정이나 방금 바뀐 memory가 보이면 먼저 사용자에게 확인한다.

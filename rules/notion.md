# 노션(Notion) 작업 시 — 필수

> `~/claude-config/CLAUDE.md` 가 import 하는 규칙 파일이다.

---

노션에 **데이터를 넣거나 고치거나 대량 조회**하기 전에 `notion-sync` 스킬을 먼저 로드한다.

한 줄 요약: **MCP 도구로 한글을 대량 적재하면 4~12%가 손상된다**(모델이 도구 인자를 재타이핑하는 구조라 프롬프트로 못 막는다). → **python이 REST API를 직접 호출**하면 손상 0·토큰 ~0. 도구는 `~/claude-config/tools/notion_page.py`.

절대 규칙 셋:
- **`push`는 파괴적이다** — 전체 삭제 후 재적재. 사람이 채우는 페이지·누적 페이지는 `notion_pages.json`의 `append_only`에 넣어 막고, 부분 수정은 블록 단위 PATCH로 한다.
- **적재 후 재조회 대조는 필수** — 어느 방식이든. 육안 비교는 놓친다.
- **조용한 실패를 의심하라** — 조회가 10,000행에서 거짓 종료하고, 200을 반환하며 무시되는 요청이 있다. 딱 떨어지는 숫자가 나오면 재조회로 확인한다.

**★ 페이지 전체를 다시 적재하는 동기화는 「본문 위에 얹힌 것」을 끊는다.** 블록을 지우고 다시 넣으므로
그 블록에 앵커된 **코멘트·편집 제안**이 본문과 분리된다. 보호 목록을 만들 때 "사용자가 타이핑한 본문"만
대상으로 잡으면 얹힌 것은 못 막는다. 재적재 전에 **"이 페이지에 코멘트나 제안이 달렸을 수 있는가"를
사용자에게 묻는다.** 되돌리기는 노션 **「페이지 기록」**이고, 재적재 전후 판본을 로컬에 날짜를 붙여 남긴다.
코멘트가 붙은 페이지는 같은 페이지에 재적재하지 말고 **새 페이지로 낸다.**

⚠⚠ **편집 제안(Suggested edits)은 수락 전까지 API 에 존재하지 않는다.** 본문 조회에도 코멘트 조회에도
**0건**으로 나오고 **화면에만 보인다**. Guest 권한 협업자는 본문을 못 고쳐 제안으로 남기므로 이 상태가 흔하다.
→ **API 0건을 "사용자 입력 없음"으로 읽지 말 것.** 사용자가 "분명히 남겼다"고 하면 브라우저로 확인한다.
⚠ **코멘트 조회는 통합의 별도 권한**이다(없으면 403 `restricted_resource`). **권한을 켜도 제안은 안 나온다** —
403 과 "대상이 아님"은 원인이 다른데 증상이 같으니 구분해서 진단할 것.

404(`object_not_found`)는 토큰이 아니라 **통합이 그 페이지에 연결 안 된 것**이다. `notion-sync` 스킬 7절 참고.

**접근 경로가 두 개이고 범위가 다르다.** REST 토큰(내부 통합)은 **명시적으로 연결된 페이지만** 보이지만, MCP 커넥터(OAuth)는 **워크스페이스 전반**이 열려 있다. 2026-08-06에 커넥터로 제목 검색 한 번에 개인 페이지가 그대로 잡혔다. 노션 작업을 안내할 때 "통합에 연결된 페이지만 보인다"고 말하지 않는다 — 가시성이나 차단을 안내할 때는 **두 경로를 모두** 짚는다.

페이지 id·프로젝트 경로는 이 리포가 아니라 **프로젝트 디렉터리의 `notion_pages.json`**에 둔다.

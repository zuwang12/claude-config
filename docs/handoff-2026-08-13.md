# 인수인계 — 저장소 정리 작업 (2026-08-13)

작업 기계: **dell** · 상태: **주 작업 완결**. 아래는 남은 판단과 다른 기계 작업이다.

## 1. 무엇을 했나

공개 저장소에 조직·프로젝트 식별자가 들어 있어 사내 규정 위반 상태였다. 히스토리를 다시
쓰고 저장소를 삭제·재생성해 해소했다. 상세 절차는 [reclone-2026-08-13.md](reclone-2026-08-13.md).

| | 전 | 후 |
|---|---|---|
| 커밋 | 39 | 30 (+ 이후 작업분) |
| 전 히스토리 식별자 | 606건 | **0건** |
| 원격 | 옛 히스토리 | 삭제 후 재생성, 태그 `v1.0` |

함께 한 것: 규칙 후보 21건 승격 · 프로젝트 문서에만 있던 범용 규칙 9건 승격 ·
`pre-commit` 식별자 차단 · `.gitignore` 화이트리스트 전환 · 훅을 복사본 방식으로 전환.

## 2. 남은 판단 (사용자만 정할 수 있다)

| # | 판단할 것 | 왜 필요한가 |
|---|---|---|
| ① | **춘이 회사 자산인가** | 맞다면 태그 고정 · push 봉인 · 세션 훅 미등록 3가지를 추가로 건다. [reclone 문서 §4](reclone-2026-08-13.md) 참고 |
| ② | **기계별 태그 고정 여부** | 규칙을 고치기도 하면 `main`, 읽기만 하면 `v1.0` 고정. 현재 dell 만 `main` |
| ③ | **규정상 보고를 할 것인가** | 안내문 ③항은 삭제와 **별개 의무**다. 보고서 초안은 사용자 요청으로 삭제했다 |
| ④ | **`~/.claude/CLAUDE.md` 의 기계 서술 정정** | 이 기계를 "회사 자산 / 원격 서버"로 적고 있으나 사외망 개인 PC 라는 확인을 받았다. 어느 쪽이 맞는지 |

③은 미이행 상태에서 피해가 발생하면 규정상 불이익이 있다. 판단만 하고 넘어가지 말 것.

---

## 3. 남은 작업 (기계별)

### 춘 · mlai · mac — 각 기계에서

**기존 clone 은 pull 이 불가능하다.** [reclone-2026-08-13.md](reclone-2026-08-13.md) 를
그 기계에서 열어 순서대로 따른다. 되돌릴 수 없는 단계 앞에 「건질 것」 절이 있다 —
특히 **`_inbox.md` 를 지우기 전에 로컬로 옮겨야 한다**(그 기계에서만 적은 관측이 거기에만 있다).

### dell — 이미 끝남

재clone 불필요(여기서 작업했다). 훅 복사·`core.hooksPath`·설정 변경 완료.
다음 세션 시작 시 `SessionStart` 훅이 정상 발화하는지가 마지막 확인 지점이다.

## 4. 정리 대상 파일 (저장소 밖)

| 경로 | 성격 | 언제 지우나 |
|---|---|---|
| `~/claude-config-backup.git` | 삭제 전 원격 미러 | 3대 재clone 완료 후 |
| `~/claude-config-fullbackup.bundle` | 로컬 전 ref 포함 백업 | 3대 재clone 완료 후 |
| `~/claude-config-repl2.txt` | 치환 목록 | 지금 지워도 된다 |
| `~/.claude/_inbox.md` | **지우지 않는다.** 규칙 후보 원본 | 계속 씀 |

⚠️ **백업 2개에는 제거하려던 식별자가 그대로 들어 있다.** 로컬 파일이라 유출은 아니지만,
다른 저장소나 백업 도구에 딸려 들어가지 않게 주의한다. 3대 재clone 이 끝나기 전에 지우면
그 기계들의 미푸시 작업을 복구할 수단이 없어진다.

## 6. 다음 세션에서 이어받는 법

```bash
cd ~/claude-config
```

경로를 직접 말하면 된다 — 파일은 저장소 안에 있으므로 어디서든 읽힌다.

## 작업 2. `_inbox.md` (append-only 수렴 지점)

**문제**: 지금은 각 세션이 규칙의 최종 문장을 직접 쓴다. 여러 세션이 같은 주제를
다르게 정리하면 충돌한다.

**해법**: 후보와 확정을 분리한다.

- `rules/` — 확정. 사람이 승인한 것만
- `_inbox.md` — append-only. 각 세션이 발견한 것을 `날짜 / 기계 / 내용`으로 **끝에 덧붙이기만** 함

append-only는 구조적으로 충돌하지 않는다. 주기적으로(세션종료준비 때) 한 세션이
inbox를 읽고 `rules/`로 승격시킨다. WORKLOG(append-only) 패턴을 config 관리에 적용하는 것.

### ⚠️ 분할 작업 세션을 열 때 (2026-08-08 실측)

- **cwd는 `~/claude-config`.** git 저장소라 Stop/SessionStart 훅이 돌고, 편집 대상이 전부 그 아래 있다.
  `~` 는 git 저장소가 아니라 Stop 훅이 아무것도 남기지 않는다.
- **미확인 부작용**: `~/claude-config` 에는 `.claude/` 가 없고 루트에 `CLAUDE.md` 가 있다.
  cwd가 여기면 그 파일이 **프로젝트 메모리로 한 번**, `~/.claude/CLAUDE.md` 의

  분할 후에는 `CLAUDE.md` 가 import 목록만 남으므로, 중복된다면 `rules/` 전체가 두 번 실린다.

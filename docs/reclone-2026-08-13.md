# 다른 기계 재clone 안내 (2026-08-13)

대상: **춘**(Windows) · **mlai**(Ubuntu 서버) · **mac**(macOS)
작업 주체: 각 기계에서 사용자가 직접. dell 에서는 할 수 없다.

---

## 0. 왜 재clone 인가

2026-08-13 에 `claude-config` 의 **히스토리를 통째로 다시 썼다.** 조직·프로젝트 식별자를
제거하기 위해 `git filter-repo` 를 돌렸고, GitHub 저장소도 삭제 후 재생성했다.

- 커밋 39개 → 30개 (식별자만 담고 있던 커밋이 빈 커밋이 되어 제거됨)
- 모든 커밋의 SHA 가 바뀌었다
- `_inbox.md` 가 히스토리에서 완전히 사라졌다

**기존 clone 은 공통 조상이 없어 `pull` 이 불가능하다.** 강제로 맞추려 하지 말고 새로 받는다.

⚠️ **기존 clone 안에는 옛 히스토리, 즉 제거하려던 식별자가 그대로 남아 있다.**
로컬 파일이라 유출은 아니지만, 아래 3번을 마친 뒤 **삭제하는 것이 이번 작업의 일부**다.

---

## 1. 먼저 건질 것을 건진다 (되돌릴 수 없는 단계 이전)

각 기계에서 순서대로 확인한다.

```bash
cd ~/claude-config && git status --porcelain && git log --oneline -3
```

### 1-1. 미커밋 수정이 있으면

새 저장소에 그대로 옮길 수 없을 수 있다(파일이 사라졌거나 내용이 치환됐다). 먼저 빼 둔다.

```bash
git -C ~/claude-config diff > ~/claude-config-uncommitted-$(date +%F).patch
```

### 1-2. 미push 커밋이 있으면

```bash
git -C ~/claude-config log --oneline origin/main..HEAD
```

출력이 있으면 그 커밋들은 **옛 히스토리 위에 얹혀 있어 cherry-pick 이 안 된다.**
패치로 뽑아 두고, 새 clone 에서 내용을 보며 손으로 다시 적용한다.

```bash
git -C ~/claude-config format-patch origin/main..HEAD -o ~/claude-config-unpushed
```

### 1-3. `_inbox.md` 가 있으면 반드시 옮긴다

이 파일은 **저장소에서 영구히 빠졌다.** 새 clone 에는 없다.
그 기계에서 적은 규칙 후보가 여기에만 있으므로, 지우기 전에 로컬로 옮긴다.

```bash
cp ~/claude-config/_inbox.md ~/.claude/_inbox.md && chmod 600 ~/.claude/_inbox.md
```

이미 `~/.claude/_inbox.md` 가 있으면 덮어쓰지 말고 **끝에 이어붙인다.**

> 앞으로 인박스는 **기계마다 로컬 파일**이다. 커밋하지 않는다. 기계 간 자동 수집은 없어졌고,
> 공유는 승격 시점에만 일어난다. 자세한 것은 그 파일 머리말에 적어 두었다.

## 2. 재clone

```bash
mv ~/claude-config ~/claude-config-old && git clone https://github.com/zuwang12/claude-config ~/claude-config
```

### 태그 고정 여부

| 그 기계에서 규칙을 **고치기도 하는가** | 하는 것 |
|---|---|
| 예 (편집·push 함) | `main` 그대로 둔다 |
| 아니오 (읽기만) | `git -C ~/claude-config checkout v1.0` 로 고정한다 |

태그를 고정하면 다른 기계가 push 해도 자동으로 따라오지 않는다. 갱신할 때마다 diff 를 보고
직접 올린다. 읽기 전용 기계에는 이쪽이 안전하다.

## 3. 설정

### 3-1. pre-commit 훅 켜기 (전 기계 공통)

`core.hooksPath` 는 **저장소 로컬 설정이라 clone 마다 따로 켠다.** 켜지 않으면 조직 식별자
차단이 동작하지 않는다.

```bash
git -C ~/claude-config config core.hooksPath .githooks
```

동작 시험. `.githooks/pre-commit` 의 패턴 목록에서 **조직 식별자 하나를 골라** README 에
넣고 커밋을 시도한다. `✋ 커밋 차단` 이 떠야 정상이다.

```bash
cd ~/claude-config && echo "probe <식별자>" >> README.md && git add README.md && git commit -m t
```

```bash
cd ~/claude-config && git reset HEAD README.md && git checkout README.md
```

> 이 문서에 식별자를 예시로 적지 않은 것은 **문서 자신이 훅에 걸리기 때문**이다.
> 훅 파일 안의 패턴은 각 낱말의 한 글자를 `[ ]` 로 감싸 같은 문제를 피하고 있다.

### 3-2. 세션 훅 (쓰는 기계만)

**저장소 경로를 직접 가리키지 않는다.** 복사해서 쓴다. 절차와 이유는
[rules/session.md](../rules/session.md) 「자동 감시(훅)」 절에 있다. 순서가 중요하다 —
설정을 먼저 바꾸면 복사 전까지 훅이 조용히 실패한다.

```bash
mkdir -p ~/.claude/hooks && cp ~/claude-config/snippets/hooks/*.sh ~/.claude/hooks/ && chmod +x ~/.claude/hooks/*.sh
```

```bash
for f in ~/.claude/hooks/*.sh; do echo '{}' | "$f" >/dev/null && echo "OK $f" || echo "FAIL $f"; done
```

그다음 `~/.claude/settings.json` 에 `rules/session.md` 의 JSON 을 **병합**한다(기존 키 보존).

### 3-3. `~/.claude/CLAUDE.md` 확인

⚠️ **이 파일을 덮어쓰지 않는다.** 기계에 따라 사양·제약·위임 규칙이 들어 있다.
`@~/claude-config/CLAUDE.md` 한 줄이 있는지만 보고, 없으면 **끝에 추가**한다.

```bash
grep -qxF '@~/claude-config/CLAUDE.md' ~/.claude/CLAUDE.md || printf '\n@~/claude-config/CLAUDE.md\n' >> ~/.claude/CLAUDE.md
```

## 4. 기계별로 다른 것

### 춘 (Windows)

- **Git Bash 유무가 미확인이다.** 없으면 `.sh` 훅 3개가 돌지 않는다.
  `bash --version` 으로 먼저 확인한다. 없으면 세션 훅은 건너뛰고 pre-commit 만 쓴다
  (pre-commit 도 `sh` 가 필요하나 Git for Windows 에는 포함돼 있다).
- **회사 자산이라면** 아래를 추가로 건다. 판단은 사용자가 한다.
  - 태그 고정(`checkout v1.0`) — 검토 없이 규칙이 따라오지 않게
  - push 봉인 — 의지가 아니라 설정으로 막는다
  - 세션 훅 미등록 — 외부 저장소 스크립트를 자동 실행할 이유가 없다

```powershell
git -C "$env:USERPROFILE\.claude\claude-config" remote set-url --push origin DISABLED
```

### mlai (Ubuntu 서버) · mac (macOS)

- `python3` 유무만 확인하면 된다. 훅은 `jq` 를 쓰지 않는다.
- mac 은 `stat -f` 계열이라 BSD 문법이다. 훅 스크립트는 이를 쓰지 않으므로 영향 없다.

## 5. 검증 (재clone 후 각 기계에서)

```bash
cd ~/claude-config && echo "커밋수: $(git rev-list --all --count)" && echo "hooksPath: $(git config core.hooksPath)" && git log --oneline -1
```

| # | 확인 | 기대값 |
|---|---|---|
| 1 | 커밋 수 | 30 이상 (재작성 후 기준) |
| 2 | `git ls-files \| grep _inbox` | 결과 없음 |
| 3 | `git config core.hooksPath` | `.githooks` |
| 4 | 조직 문자열로 커밋 시도 | **차단됨** |
| 5 | 세션 훅 파이프 시험 | 3개 모두 OK |
| 6 | `~/.claude/CLAUDE.md` | 기존 내용 보존 + import 한 줄 |

## 6. 옛 clone 삭제

위 5번이 전부 통과하고, 1번에서 뽑아 둔 패치를 새 clone 에 반영한 뒤에 지운다.

```bash
rm -rf ~/claude-config-old
```

⚠️ **1-3 의 `_inbox.md` 이관을 했는지 다시 확인하고 지운다.** 그 기계에서만 적은 관측이
여기에만 있을 수 있다. 지우면 복구할 수 없다.

---

## 7. 이 문서를 언제 지우나

세 기계가 모두 끝나면 지운다. 재clone 은 일회성 작업이고, 남겨 두면 다음에 읽는 사람이
지금도 해야 하는 일로 오인한다. 재발 방지 규칙은 이미 `rules/` 와 `pre-commit` 에 들어갔다.

# KiCad 보드 배치 계측

실패로 배운 것이다. 보드를 "그냥 열어서 보기" 전에 읽는다.

## 1. 핵심 — 여는 것만으로 원본이 바뀐다

**KiCad는 프로젝트를 여는 것만으로 파일을 쓴다.** 저장 버튼을 누르지 않아도 그렇다.
실측(KiCad 10, 구버전 포맷 파일):

| 대상 | 결과 |
|---|---|
| `.kicad_pcb` (보드) | 변경 없음 (SHA256 일치) |
| `.kicad_pro` (프로젝트) | **신형 포맷으로 덮어씀** |
| `.kicad_prl` | 새로 생성 (뷰 설정) |
| `.history/` | **remote 없는 git 저장소 자동 생성.** 보드 변환본이 "Autosave"로 커밋됨 |

고객 데이터·원본을 다룰 때는 **열기 전에** 되돌릴 사본(tar 등)을 확보하고 체크섬을 떠 둔다.
작업 후 재귀 비교로 무엇이 바뀌었는지 확정한다. "보기만 할 것"이라는 이유로 건너뛰지 않는다.

정리할 때는 KiCad를 먼저 종료한다. 열려 있으면 닫으면서 다시 쓴다.

## 2. GUI로는 배치 비교가 안 되는 경우가 있다

**KiCad의 연결선(ratsnest)은 아직 배선되지 않은 연결만 그린다.** 배선이 끝난 보드는
배선 레이어를 꺼도 연결선이 0개다. 없는 것이라 켜고 끄는 문제가 아니다.

따라서 "배선된 원설계"와 "배치만 있는 결과물"을 같은 시각화로 비교하려면
GUI가 아니라 **파일을 직접 파싱해서 연결선을 계산**해야 한다. 그래야 양쪽이 같은 기준이 된다.

## 3. ★ 회전은 `(at)` 각도 필드에 없을 수 있다

생성기가 만든 파일에서 부품 회전을 집계했더니 **전 부품이 0도**로 나왔다.
실제로는 회전이 `(at x y)` 각도 자리가 아니라 **패드·코트야드 로컬 좌표에 이미 구워져**
있었다. 각도 필드는 값이 0인 게 아니라 처음부터 비어 있었고, 없는 필드를 세고 있었던 것이다.

**판별법**: 원문에서 `(at x y rot)` 형태(숫자 3개)가 몇 개인지 직접 센다. 0개면 그 파일의
회전은 다른 곳에 있다.

**측정법**: 기준 보드와 같은 부품끼리 **패드 오프셋 집합을 0/90/180/270도 회전시켜
일치하는 각도를 찾는다.** 이것이 상대 방향의 정답이다.

일반화하면, 지표가 정확히 100%나 0%로 떨어지면 결론 전에 측정 대상이 맞는지 의심한다.
"필드가 비어 있음"과 "값이 0"은 다르다.

## 4. 도구

`~/Developer/pcb-placement-compare/` (mac 로컬. 다른 기계에는 없다)

| 파일 | 역할 |
|---|---|
| `pcb_placement.py` | s-expression 파서 + `Board` 클래스 + 지표 계산 |
| `render_compare.py` | 두 보드를 동일 기법으로 SVG 렌더 + 비교표 HTML |

```bash
python3 ~/Developer/pcb-placement-compare/render_compare.py <기준>.kicad_pcb <비교>.kicad_pcb <출력>.html
```

의존성 없음(표준 라이브러리만). 배선·zone은 읽지 않으므로 배선 여부와 무관하게 동작한다.
첫 번째 인자가 상대 비교(이동 거리·방향 일치)의 기준판이 된다.

## 5. 지표 정의

| 지표 | 정의 | 읽는 법 |
|---|---|---|
| 연결선 총 길이 | 네트별 패드 절대좌표의 유클리드 **최소신장트리** 합 | KiCad ratsnest와 같은 구성. 배치 품질의 1차 지표 |
| HPWL | 네트별 바운딩박스 반둘레의 합 | 배치기가 보통 직접 최소화하는 값 |
| 코트야드 겹침 쌍 | 같은 면에서 축정렬 코트야드가 교차하는 부품 쌍 수 | **제조 가능성 지표.** 배선 길이보다 무겁다 |
| 최근접 부품 간격 | 부품 중심 기준 최근접 거리의 중앙값 | 작아지면 뭉친 것 |
| 좌표 동일 부품 | 기준판과 좌표가 정확히 같은 부품 수 | **배치기가 실제로 몇 개를 옮겼는지.** 이게 작으면 나머지 지표 해석이 달라진다 |
| 방향 일치 | 3절 방식으로 잰 상대 회전이 0도인 부품 수 | |

**배치 범위(부품 bbox)가 양쪽 동일하게 나오면 의심하지 말고 그대로 해석한다.**
외곽을 정하는 커넥터류가 고정돼 있으면 실제로 같은 값이 나온다. 이때는 "밀도 차이" 서사가
성립하지 않으므로, 연결선·겹침 쪽으로 판정 근거를 옮긴다.

## 6. 동봉 문서의 수치를 그대로 인용하지 않는다

보드 묶음에 딸려 오는 README·요약 문서의 비율은 다른 도면 기준이거나 다른 정의일 수 있다.
실측에서 문서의 "66%"가 해당 도면에서는 19.7%였다. **인용 전에 그 도면에서 직접 잰다.**
차이가 나면 어느 쪽이 틀렸다고 단정하지 말고, 정의가 다를 가능성을 함께 보고한다.
